# 75EC 改键台

给 2015 年的宁芝（NIZ / Plum）**75EC-XRGB** 静电容键盘做的网页改键工具。官方 Windows 软件早就找不到了，这个页面通过本地桥接直接读写键盘板载配置，不需要安装驱动，也不向任何服务器发送数据。

## 为什么需要本地桥接

Chrome 的 WebHID 会把带键盘功能的 HID 设备列为受保护设备，网页拿不到 75EC 的配置接口（实测选择器里根本不会出现它）。所以 `start.command` 会启动一个只监听 `127.0.0.1` 的 Node 进程，用 `node-hid` 和键盘通信；网页通过本机 HTTP 接口读取和写入。浏览器里看到的仍然是普通网页，不需要安装浏览器扩展，也不需要给 Chrome HID 权限。

## 使用

1. 确认键盘已经插好。
2. 双击 `start.command`。它会在第一次运行时安装 `node-hid`，启动本地桥接，并用 Chrome 打开页面。
3. 页面会自动读取键盘，显示 75 个键、2 层配置和固件版本。没读到就点右上角「连接键盘」重试。
4. 点键盘上的任意键，在右侧选「普通层」或「Fn 层」，搜索功能并选择。
5. 点「写入键盘」。写入前会自动下载一份当前配置的 JSON 备份；写入后会自动读回并逐键校验。

关闭终端窗口即停止本地桥接。端口从 8787 开始，被占用会自动往后找。

> 第一次运行时 macOS 可能要求终端访问输入设备：系统设置 → 隐私与安全性 → 输入监控，允许你用的终端（Terminal / iTerm）后重试。
>
> 需要 Node.js 20 或更高版本。项目里已经装好 `node_modules`，移动到别的电脑时 `start.command` 会自动重新安装。

## 键盘的两层

- **普通层**：直接按键时生效。
- **Fn 层**：按住空格右侧的 **Fn** 键时生效。读出来的 Fn 层已经有 WASD 方向键、媒体控制、背光控制等。

读取/写入的是键盘**当前模式**下的配置。如果键盘切到了另一个模式（例如 Fn+Delete 的「编程键盘」），先切回来再点「读取」。

## 当前配置里的一个细节

读取到的普通层把物理键 **右 Shift**（键位 67）映射成了 **Up 上箭头**。这应该是很多年前留下的自定义配置，网页会原样显示；想恢复的话，选中该键，右侧会提示「改回 Shift」，或者手动选择「右 Shift」。

## 备份

- `backups/75EC-XRGB-original-2026-11-18.json`：第一次读取到的原始配置（150 条：2 层 × 75 键），请保留。
- 每次写入前页面会自动下载 `niz-75ec-before-write-*.json`，同时写一份到浏览器 localStorage。
- 「导出」保存网页里当前的配置；「导入」把备份载入网页，标记差异后再点「写入键盘」恢复。
- 导入不会自动写键盘，必须再点写入。

## 安全

- 写入过程中不要拔线、关闭页面或切换键盘模式。
- 协议写入的是整张键位表（150 条），不是单键增量；中途失败时键盘可能处于部分写入状态，重新写入一次即可恢复。
- 桥接在写入前会重新读取键盘并和你页面里的基线比对；键盘上的配置变过时会拒绝写入，提示先重新读取。写入后还会读回逐键比对。
- 如果写入后读回校验失败，页面会保留未修改前的备份文件，可以随时导入恢复。
- 本地桥接只监听 `127.0.0.1`，接口需要启动时生成的随机令牌；其他网站无法调用。

## 遇到问题

- **提示「配置接口正被另一个程序占用」**：同一时间只允许一个进程访问键盘的配置接口。关闭其他改键台终端窗口后重试；仍然失败就拔插一次键盘。重复双击 `start.command` 不会重复启动，只会打开已经在运行的页面。
- **页面提示「令牌不正确，请刷新页面」**：桥接重启过，旧标签页里的令牌失效了，刷新页面即可。
- **提示找不到键盘**：确认数据线插好、键盘没有切到无线模式；插好后点「连接键盘」重试。

## 协议（逆向结果）

来自这台键盘的实测 + [cho45/niz-tools-ruby](https://github.com/cho45/niz-tools-ruby) 的命令集：

- USB HID：VID `0x0483` / PID `0x5026`，配置接口 `usagePage 0x8C / usage 0x01`（interface 1）。键盘输入是 interface 0，consumer 是 interface 2。
- HID output report：report ID 0，64 字节 body：`[cmd_hi, cmd_lo, 62 bytes payload]`。
- 命令：
  - `0xF9` 读版本 → `"75EC(XRGB);V1.2.16;V1.3;"`
  - `0xF2` 读全部键位 → 每个键一条 input report：`00 F0 level key 00 flag hw 00...`，以 `F6...` 结束
  - `0xF1` 开始写入
  - `0xF0` 每个键：`level key 00 hasValue hw`
  - `0xF6` × 62 结束写入
- `level`：1 = 普通层，2 = Fn 层。75EC 只返回 2 层。
- `hw`：0–255 的固件键码；`0` 表示无功能。当前键位与键码的对应关系见 `index.html` 里的 `K` 表。

实测记录：

- 版本：`75EC(XRGB);V1.2.16;V1.3;`，75 键。
- 读全部：2 层 × 75 键 = 150 条。
- 原样写回后读回完全一致；单独改一个键再读回、再恢复也一致。

## 文件

- `index.html`：整个网页应用（无构建、无外部依赖）。
- `bridge.mjs`：本地桥接，负责静态页面和 `/api/read`、`/api/write`。
- `package.json`：只依赖 `node-hid`。
- `start.command`：启动桥接并打开 Chrome。
- `backups/`：原始配置备份。
